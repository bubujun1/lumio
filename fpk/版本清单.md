## 功能新增（v1.0.1 末次增补）·「检查更新」

家长端「设置与管理 → 数据与维护」区内新增「🔄 检查更新」按钮（仅系统管理员可见，依赖 `st.me.isAdmin`）。行为：

- **后端**（`http.js` 新增 `GET /api/update/check`，管理员专属）：读取项目根 `manifest` 的 `version` 作为当前版本，代理请求 GitHub Releases `repos/bubujun1/lumio/releases/latest`，用 `cmpVer` 做三段式语义化版本比较，返回 `{ ok, current, latest, updateAvailable, url, published_at }`；6s `AbortController` 超时 + try/catch 兜底，离线时优雅返回「无法连接更新服务器」。
- **前端**（`pages-admin.js` 按钮 + `handlers-shell.js` 的 `actCheckUpdate`）：弹 `okOnly` 模态，拉取 `/api/update/check` 后渲染「发现新版本 vX（前往下载）」或「已是最新版本」或错误态；`urlOf()` 限定仅允许 `github.com` https 链接，渲染全部经 `esc()` HTML 转义。

实现时一并修复的两个后端缺陷（否则该特性无法正确读取当前版本号）：

| 编号 | 文件 | 整改内容 |
| --- | --- | --- |
| F1 | `config.js` | `APP_DIR` 此前定义但**未导出**（`module.exports` 遗漏），导致 `http.js` 解构到的 `APP_DIR` 为 `undefined`、`path.join(APP_DIR, …)` 抛错被吞、当前版本号恒为 `0.0.0`。已在导出列表补 `APP_DIR` |
| F2 | `http.js` | 在 `config` 解构中补 `APP_DIR` 引入，使 `/api/update/check` 能正确读取根目录 `manifest` 的真实版本 |
| F3 | `http.js` | **发布后用户实测缺陷（且本修复无效）**：安装 `v1.0.1` 后「检查更新」仍报当前版本 `0.0.0`。当时的判断 = 自检写死 `path.join(APP_DIR, '..', 'manifest')`，而 `cmd/main` 把 `APP_DIR` 设为安装根目录，故 `../manifest` 指向不存在的路径。改为多候选路径解析。⚠️ **该修复在用户实机上依然无效**（F3 只猜了 3 个位置、且异常被静默吞掉），真实根因与最终修复见下方 v1.0.2 · F4 |

## v1.0.2 缺陷修复 · F4：F3 为何无效（用户实测仍报 0.0.0）

用户安装含 F3 修复的 v1.0.1 后，「检查更新」**依旧**显示当前版本 `0.0.0`。复查后确认 F3 的判断方向错了——它仍在**猜** `manifest` 的位置，而 `manifest` 是 fpk **顶层**文件（不在 `app.tgz` 内），其安装后的落位并不由本仓库决定：只有 `app/` 内的文件（如 `server/server.js`、`ui/index.html`）才保证落在 `${APP_DIR}`。多候选路径只是换了几种猜法，全都落空时依旧静默回退 `0.0.0`，且异常被 `catch {}` 吞掉、日志无线索。

结构性结论：**应用自身的版本号不该依赖一个由外部框架放置、位置不可控的文件。** 故改为：

| 编号 | 文件 | 整改内容 |
| --- | --- | --- |
| F4-a | `lib/config.js` | 新增 `resolveAppVersion()`：从 `__dirname` **逐级上溯 6 层**找 `manifest`（覆盖任意嵌套深度），并以 `APP_DIR/manifest`、`APP_DIR/../manifest` 兜底；候选逐个记录去重 |
| F4-b | `lib/config.js` | `readManifestVersion()` 解析前先**校验 `appname = lumio`**，避免误读邻近目录里其它应用的 `manifest`（否则会把别人的版本号当自己的） |
| F4-c | `lib/config.js` | 新增 `APP_VERSION_FALLBACK = '1.0.2'` 内置常量：全部候选落空时返回它，**保证任何情况下都不再出现 `0.0.0`**；注释标明发版时须与 `manifest` 同步（回归测试会断言两者一致） |
| F4-d | `lib/http.js` | 删除原内联解析块（18 行）改调 `resolveAppVersion()`；响应新增 `versionSource`（实际命中的 manifest 路径）与 `versionFallback`（是否走了兜底），**排障可直接看接口返回，不必再猜** |
| F4-e | `server/server.js` | 启动即打印 `[version] <ver> 来源=<path>`；走兜底时额外告警「未找到 manifest，请检查安装布局」，杜绝再次静默漂移 |

兼容性：解析正则同时兼容 LF/CRLF 行尾（fnpack 会把 `manifest` 强制写成 CRLF）与 `appname` 带引号形态；`manifest` 仍为权威来源（若与内置常量不一致以 `manifest` 为准，避免常量过期反向覆盖）。
