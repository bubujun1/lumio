# Lumio

> 飞牛 fnOS 上的家庭积分应用：家长发布任务，孩子完成赚积分，积分可兑换奖励或现金 —— 让激励有据可查，让约定说到做到。

**Lumio** 面向在飞牛 NAS（fnOS）上使用家庭积分激励的家长与孩子。它把「做家务换零花钱」这件事搬到 NAS 上：任务、积分、兑换、留言全流程可追溯，数据只存在本机，不上传任何云端。

- **应用形态**：fnOS 应用包（`.fpk`），通过应用中心安装
- **运行环境**：飞牛 fnOS（依赖 `nodejs_v24`，应用中心自动安装）
- **最新版本**：v1.0.2
- **许可协议**：MIT

## 核心能力

### 家长端

| 能力 | 说明 |
| --- | --- |
| 任务管理 | 发布每日 / 每周 / 每月 / 限时 / 临时五类任务，可指定分配给哪些孩子，自由上架下架 |
| 积分发放 | 直接给孩子发币或扣币，可附一句留言，实时出现在孩子首页 |
| 审核中心 | 孩子提交的任务完成申请在此处理，可通过或退回并留言说明 |
| 孩子管理 | 新建 / 编辑 / 删除孩子，绑定或解绑孩子的飞牛账号 |
| 家长身份绑定 | 可把非管理员的飞牛账号绑定为「爸爸 / 妈妈」，其权限与管理员等同，解绑后立即收回 |
| 商店管理 | 配置可兑换的奖励（特权或实物）与现金，设定所需积分、库存与有效期 |
| 积分记录 | 全部积分流水，含原因、操作人、变化前后余额，可按孩子筛选 |
| 家庭设置 | 家庭名称、家长称呼、积分兑换比例、任务是否需审核、孩子能否许愿与留言 |

### 孩子端

| 能力 | 说明 |
| --- | --- |
| 我的成长 | 积分余额、等级进度、今日获得、折合人民币，家长留言气泡与心愿进度 |
| 任务 | 任务卡片显示今天还能做几次、当前状态（待确认 / 已完成 / 做满） |
| 商店 | 用积分兑换奖励，积分不足时提示还差多少 |
| 心愿 | 许下心愿、查看进度、阅读家长的鼓励 |

### 亲子互动

- 孩子提交任务或兑换 → 家长端出现待审核提醒 → 处理结果实时同步到孩子端
- 双向留言：孩子的靠右、家长的靠左，家长端可查看完整对话
- 孩子许愿 → 家长在总览看到并送上鼓励
- 孩子端首页 4 秒轮询，家长处理后无需手动刷新

## 使用场景

**日常习惯养成**
把「整理房间」「早晚刷牙」「阅读 30 分钟」设为每日任务，孩子完成后一键提交，家长审核通过即到账。相比口头催促，积分记录能清楚回答「这个月到底坚持了几天」。

**阶段性目标激励**
考试前设一个「每复习完一科」的一次性临时任务，用较高积分奖励；家长可视完成情况追加鼓励，形成正反馈。

**零花钱与特权兑换**
在商店配置「看动画片 30 分钟」「免做一次家务」等特权，也可以配置现金兑换（由家长逐条填写面额）。孩子攒够积分自己下单，兑换免审核，确认即扣分即得。

## 特性亮点

- **无需账号密码**：完全复用 fnOS 登录态，不建自有账号体系，不存任何密码
- **数据不出 NAS**：所有数据保存在本机 `@apphome` 目录，不访问外网、不上传云端
- **不暴露网络端口**：经 fnOS 统一网关的 Unix Socket 通信，不对外开放 TCP 端口
- **零依赖、无构建链**：后端不依赖任何 npm 包，前端为原生 ES 模块，改完源码即打包
- **升级保留数据**：覆盖升级不丢数据，卸载默认也不删除

## 安装

### 环境依赖

| 依赖 | 说明 |
| --- | --- |
| 飞牛 fnOS | 必需。需为 1.2.0 及以上 |
| `nodejs_v24` | `manifest` 中已声明，应用中心会自动安装，无需手动操作 |
| 统一网关 | fnOS 自带，用于注入身份信息 |

无需数据库、无需 Docker、无需手动安装 Node.js。

### 安装步骤

1. 下载安装包 `lumio-v1.0.2.fpk`（见 [Releases](https://github.com/bubujun1/lumio/releases)）
2. 飞牛桌面 → **应用中心** → 右上角设置 → **手动安装应用** → 选择 `lumio-v1.0.2.fpk`
3. 安装完成后桌面出现「Lumio」，点开即进入家长端

### 让孩子也能看到图标（安装后必做一次）

若孩子在自己的桌面上看不到「Lumio」图标，请管理员设置：

> 飞牛桌面 → 系统设置（齿轮）→ 应用 → Lumio → 「谁可以访问」→ 选择 **设备内所有用户可以从桌面访问** → 保存

> 应用配置中已默认 `allUsers: true`，但飞牛仅在**首次安装**时套用该默认值，覆盖升级不会重新套用，因此升级后也建议确认一次。

### 首次使用：把孩子绑定到飞牛账号

Lumio 没有自己的账号体系，孩子的身份通过绑定飞牛账号确定。步骤：

1. 在家长端「孩子」页**新建孩子**，填写名字与初始积分
2. 让孩子用自己的飞牛账号打开一次 Lumio（这一步只是让应用"见"到他）
   - 若对方尚未访问过，绑定时会提示「没找到飞牛用户」——这是防止绑错人的保护
3. 回到「孩子」页，在「来访过但未绑定的飞牛用户」中点击 **绑定给孩子…**
4. 完成。此后孩子用自己的飞牛账号打开 Lumio 即直接进入孩子端，**无需密码、无需输入账号**

## 角色与权限

| 角色 | 判定条件 | 权限 |
| --- | --- | --- |
| 管理员 | 飞牛系统管理员 | 全部权限，另可绑定/解绑其他家长身份 |
| 家长 | 非管理员，但被绑定为「爸爸 / 妈妈」 | 与管理员等同（除解绑家长身份外） |
| 孩子 | 非管理员，且已绑定到某个孩子 | 仅孩子端：做任务、许愿、兑换、留言 |
| 未绑定 | 非管理员，且未绑定任何身份 | 仅显示引导页，提示等待绑定 |

身份由 fnOS 统一网关在转发请求时注入的 `X-Trim-Userid`、`X-Trim-Username`、`X-Trim-Isadmin` 三个请求头决定，**服务端据此判定，前端无法伪造**。

## 配置项

### 环境变量

后端读取的环境变量如下。生产环境由 fnOS 在启动应用时自动注入，通常无需手动设置。

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `APP_DIR` | 应用安装目录 | 源码运行时为 `app/` |
| `DATA_DIR` | 数据目录（存放 `db.json`） | `@apphome/lumio/data` |
| `VAR_DIR` | 可变状态目录 | 同 `DATA_DIR` |
| `PORT` | TCP 监听端口（仅未启用 Socket 时生效） | `8787` |
| `BASE_PATH` | 反向代理路径前缀 | `/app/lumio` |
| `MONITOR_SOCKET_PATH` | Unix Socket 路径；设置后不再监听 TCP | 空 |
| `APPNAME` | 应用名 | `lumio` |
| `LUMIO_DEV` | 本地调试开关，**生产环境严禁开启** | 未设置 |

> ⚠️ `LUMIO_DEV=1` 会启用 `X-Dev-*` 头模拟身份，仅用于本机开发调试。生产环境设置该变量等同于开放管理员权限。

### 家长可配置项

在「设置」页中调整，保存后立即生效：

| 配置项 | 说明 |
| --- | --- |
| 家庭名称 | 显示在孩子端首页 |
| 家长称呼 | 家长留言时孩子看到的称呼，如「爸爸」 |
| 积分兑换比例 | 多少积分折合 1 元现金 |
| 过期返还比例 | 奖励卡券过期后按比例返还积分，0 表示不返还 |
| 任务需要审核 | 关闭后孩子完成任务即到账 |
| 允许孩子许愿 | 关闭后孩子无法主动许愿 |
| 允许孩子留言 | 关闭后孩子无法主动给家长留言 |
| 每周目标 | 孩子端的每周积分目标 |

## 本地开发

无构建链，克隆后可直接运行。

```bash
# 以 TCP 方式本地启动后端（绕开 Unix Socket）
PORT=8787 BASE_PATH=/app/lumio APP_DIR=./app \
DATA_DIR=./tmp/data VAR_DIR=./tmp/data \
node app/server/server.js
```

浏览器预览需要开启调试身份开关：

```bash
LUMIO_DEV=1 node app/server/server.js
```

随后用 `X-Dev-Userid`、`X-Dev-Username`、`X-Dev-Isadmin` 三个请求头模拟身份（如 `X-Dev-Userid: 1001`、`X-Dev-Username: tester`、`X-Dev-Isadmin: 1`）。

打包：

```bash
fnpack build      # 在工程根目录执行，产出 lumio.fpk
```

## 部署安全

本应用没有自有账号体系，身份完全依赖网关注入的请求头，后端对其无条件信任。因此部署时必须守住：

1. **必须置于 fnOS 网关之后**，不可直接暴露。设置了 `MONITOR_SOCKET_PATH` 时后端只监听 Unix Socket，对外无 TCP 端口；若该变量缺失、后端回退到 TCP 监听，请确保该端口不对 NAS 网段外的任何主机可达。
2. **网关必须剥离客户端自带的 `X-Trim-*` / `X-Dev-*` 头**，再注入可信头。这是安全边界成立的真正前提。
3. **生产环境禁止设置 `LUMIO_DEV`**，启动日志中的 `dev=` 应为 `false`。

部署后自检：

```bash
# 确认走 Socket（应为 true）
curl <网关地址>/app/lumio/api/health

# 确认网关剥离了外部伪造头（role 绝不能是 admin）
curl -H 'X-Trim-Isadmin: true' <网关地址>/app/lumio/api/identity
```

## 数据与隐私

| 项目 | 位置 |
| --- | --- |
| 数据文件 | `/vol1/@apphome/lumio/data/db.json`（随 `TRIM_PKGHOME` 变化） |
| 运行日志 | `/vol1/@appdata/lumio/info.log` |

- 数据保存在 NAS 本机，**不访问外网、不上传任何云端**
- 存储为单个 JSON 文件，直接复制整个 data 目录即可备份
- 覆盖升级保留数据；卸载应用时也**不会删除数据**，如需清理请手动删除 data 目录
