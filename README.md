# ✨ Lumio · 飞牛 fnOS 应用

> 家庭积分与零花钱管理。孩子完成任务赚积分、攒够积分实现心愿；家长发布任务、发放奖励、审核兑换。
> 所有数据保存在 NAS 本机，不上传任何云端。

---

## 一、账号与权限模型（本应用的核心）

本应用**不使用自己的账号密码体系**，而是完全复用飞牛 fnOS 的登录态。
判断依据来自飞牛统一网关在转发请求时注入的三个可信身份头（飞牛官方文档「统一网关 → 会话校验和用户 Header」）：

| 请求头 | 含义 | 示例 |
| --- | --- | --- |
| `X-Trim-Userid` | 当前登录飞牛用户的 UID | `1001` |
| `X-Trim-Username` | 当前登录飞牛用户名 | `xiaoming` |
| `X-Trim-Isadmin` | 是否为飞牛系统管理员 | `true` / `false` |

由此得到三种角色，**服务端判定，前端无法伪造**：

| 角色 | 判定条件 | 能做什么 |
| --- | --- | --- |
| **家长** | `X-Trim-Isadmin = true` | 全部管理权限：建孩子、绑定飞牛账号、发布任务、发/扣积分、审核、管奖励、改设置 |
| **孩子** | 非管理员，且其 UID 已被家长绑定到某个孩子 | 只能看到自己的成长主页：做任务、许愿、兑换、留言 |
| **未绑定** | 非管理员，且未被绑定 | 只看到「等待家长绑定」引导页（显示自己的用户名与 UID，方便告诉家长） |

### 绑定流程（家长指定，孩子零操作）

1. 家长（飞牛系统管理员）在飞牛桌面打开「Lumio」→ 底部**孩子** → **新建孩子**。
2. 让孩子用自己的飞牛账号打开一次本应用（这一步只是让应用"见"到他）。
   > 若对方还没访问过，绑定会提示「没找到飞牛用户 xxx」——这是防止绑错人的保护。
3. 家长回到**孩子**页：在「来访过但未绑定的飞牛用户」里点**绑定给孩子…**，或点某个孩子的**绑定/改绑**。
4. 完成后，孩子用自己的飞牛账号打开应用，就直接进入应用，**不需要密码、不需要输账号**。

### ⚠️ 让普通用户能看到图标（必做一次）

`app/ui/config` 里已设 `allUsers: true`，但飞牛只在**首次安装**时套用该默认值。
如果孩子桌面上没有「Lumio」图标，请由管理员设置：

> 飞牛桌面 → 系统设置（齿轮）→ 应用 → Lumio → 「谁可以访问」→ 选择**设备内所有用户可以从桌面访问** → 保存

（`allUsers` 是"首次安装默认值"，覆盖升级不会重新套用，所以升级后也需要确认一次。）

## 二、功能

### 家长端（飞牛管理员）

| 模块 | 说明 |
| --- | --- |
| **总览** | 孩子数、积分总数、今日变化；待处理审核（可直接通过/退回并留言）；每个孩子的快捷发币/留言；今日动态 |
| **审核** | 任务完成申请、兑换申请，一键通过/退回（可写留言给孩子）；最近处理记录 |
| **孩子** | 新建/编辑/删除孩子；**绑定与解绑飞牛账号**；发/扣积分；留言；未绑定用户一键绑定 |
| **任务** | 日常任务（每天可做 N 次）与一次性任务；可指定分配给哪些孩子；启用/停用 |
| **商店** | 奖励项：名称、图标、所需积分、库存（留空=不限量）、普通奖励或现金；上架/下架 |
| **记录** | 全部积分流水，含原因、操作人、变化前后余额，可按孩子筛选 |
| **设置** | 家庭名称、家长称呼、兑换比例（N 积分 = 1 元）、任务/兑换是否需要审核、孩子能否许愿/留言 |

### 孩子端（已绑定的飞牛用户）

| 模块 | 说明 |
| --- | --- |
| **我的成长** | Lumio吉祥物 + 积分余额 + 等级进度 + 今日获得 + 折合人民币；家长留言气泡；心愿进度；最近积分流水 |
| **任务** | 我的任务卡片，显示今天还能做几次、当前状态（待确认/已完成/做满） |
| **商店** | 用积分兑换奖励；积分不够时按钮变为「还差 N 个」 |
| **心愿** | 许愿、看心愿进度、看家长的鼓励语 |

### 亲子互动链路（双向）

- 孩子提交任务 / 申请兑换 → **家长端出现待审核角标** → 通过/退回并留言 → 孩子端收到留言气泡与提醒
- 家长发/扣积分可附带一句话，直接出现在孩子首页
- 孩子许愿 → 家长能看到并「加油」鼓励；孩子也可以主动给家长留言
- 双向留言弹窗（自己的留言靠右、家长的靠左），家长端可查看完整对话
- 孩子端首页有 4 秒轮询，家长端的处理结果会自动刷新出来

## 三、安装

1. 飞牛桌面 → **应用中心** → 右上设置 → **手动安装应用** → 选择 `lumio.fpk`
2. 安装完成后桌面出现「Lumio」，点开即进入家长端
3. 按上面「绑定流程」建孩子并绑定
4. 首次使用建议改一下「设置」里的家庭名称与家长称呼

> 安装依赖 `nodejs_v24`（`manifest` 中已声明，应用中心会自动装）。

## 五、排障

| 现象 | 处理 |
| --- | --- |
| 页面提示「请从飞牛桌面打开」 | 本应用需要飞牛登录态，请从飞牛桌面图标进入；浏览器直接访问 `:5666` 根路径拿不到身份 |
| 页面能开但一直转圈/数据加载不出来 | 打开诊断页 `http://<NAS_IP>:5666/app/lumio/debug` 查看当前身份、角色、数据目录与最近日志 |
| **完全没有样式**、一直停在「Lumio 正在醒来…」 | 外部资源（css/js）被浏览器解析到错误路径而 404。`index.html` 的外部引用**必须带网关前缀**（`__APP_BASE__/css/…`、`__APP_BASE__/js/main.js`），**不能写裸相对路径** `css/…`——飞牛手机端 iframe 以 `/app/lumio`（无尾斜杠）打开时，裸相对路径会被解析成 `/app/css/…` → 404。v2.0.56 已修（⚠ 勿装 v2.0.55）；可用 `node probe-asset-url.cjs` 三种 URL 形态对比定位 |
| 家长端「任务 / 待处理」卡片的**标题逐字竖排**、挤成一团 | 卡片网格列数过密。`.grid4` 必须是**按屏宽渐进**的列数（基准单列 → 560px 2 列 → 860px 3 列 → 1100px 4 列），**不可写成固定 3 列**：390px 手机上 3 列会让每张卡宽仅约 100px，卡内 40/44px 图标 + 间距吃掉后标题容器只剩 **27px**（审核卡 **12px**），中文按字符换行即成一列一字。v2.0.57 已修 |
| 应用中心点「启用」失败 | 看 `/vol1/@appdata/lumio/info.log` 与 `app.log`；SSH 下可执行 `bash /var/apps/lumio/cmd/main start` 看真实报错 |
| 孩子看不到应用图标 | 见上面「让普通用户能看到图标」 |
| 孩子打开后显示「还没有被家长绑定」 | 家长到「孩子」页把该用户名绑定到某个孩子 |


## 七、本地开发与验证

```bash
# 以 TCP 方式本地起后端（绕开 Unix Socket）
PORT=8787 BASE_PATH=/app/lumio APP_DIR=./app \
DATA_DIR=./tmp/data VAR_DIR=./tmp/data \
node app/server/server.js

# 本地浏览器预览（无网关注入身份，需要开启开发兜底）
LUMIO_DEV=1 node app/server/server.js
# 之后用 X-Dev-Userid / X-Dev-Username / X-Dev-Isadmin 头模拟身份
```

打包：在工程根目录执行 `fnpack build`，产出 `lumio.fpk`。

### 部署边界（安全铁律 · 必须读）

本应用**没有自己的账号密码体系**，身份 100% 来自飞牛网关注入的 `X-Trim-Userid / X-Trim-Username / X-Trim-Isadmin` 三个头。后端**无条件信任**这些头——这是设计前提，也是唯一的安全边界。后端代码（`auth.js`）对这三个头**先到先用**：客户端若能在网关之外带上 `X-Trim-Userid:<任意>` + `X-Trim-Isadmin:true`，就会被当成管理员。因此部署时必须守住下面三条：

1. **必须置于 fnOS 网关之后，禁止任何直接暴露。** 代码默认 `server.listen(PORT, '0.0.0.0')` 会监听 TCP 全网卡；只有当环境变量 `MONITOR_SOCKET_PATH` 被设置时，后端才改为只监听 Unix Socket（此时对外**没有 TCP 端口**）。fnOS 生产环境会注入 `MONITOR_SOCKET_PATH` 走 socket；**若因任何原因该变量为空，后端会回退到 TCP `0.0.0.0:PORT`，此时务必靠网关/防火墙确保该端口不对 NAS 网段外的任何主机可达，绝不映射公网。**
2. **网关必须剥离客户端自带的 `X-Trim-*` / `X-Dev-*` 头，再注入可信头。** 这是边界成立的真正前提：只要客户端能自己带上 `X-Trim-Isadmin:true`，后端就当成管理员。fnOS 网关默认会做这件事，但部署/排障时必须能确认它生效（见下方自检第 4 条）。
3. **生产环境绝对禁止设置 `LUMIO_DEV=1`。** 该变量会开启 `X-Dev-*` 头模拟身份（`auth.js` 在无网关注入头时回退到 `X-Dev-*`），等于把管理员权限拱手送给任何能发 HTTP 请求的人。`cmd/main` 不会设置它；只有本机无网关调试时才手动加。

### 启动前自检清单（每次部署 / 升级后过一遍）

- [ ] **不直接暴露**：确认应用只经飞牛桌面 / 网关访问，`:PORT` 没有映射到公网、也没有暴露给不可信网段（如需走 socket：见第 1 条，确认 `MONITOR_SOCKET_PATH` 已注入）。
- [ ] **未开 LUMIO_DEV**：确认运行环境没有 `LUMIO_DEV` 变量；启动日志里 `dev=` 应为 `false`。
- [ ] **监听方式正确**：访问 `/api/health`，返回里 `socket` 应为 `true`（socket 模式，无 TCP 端口）；若走 TCP，确认端口已被网关 / 防火墙收敛。
- [ ] **网关注入且剥离外部头（最关键）**：在**网关侧**用 `curl` 发两条请求——
  - `curl <网关地址>/app/lumio/api/identity` → 未登录时应返回 `role: "noauth"`（或你真实的非管理员身份），`gatewayHeaders` 反映网关是否注入了头。
  - `curl -H 'X-Trim-Userid: spoof' -H 'X-Trim-Isadmin: true' <网关地址>/app/lumio/api/identity` → 返回 `role` **必须不是** `admin`。若变成 `admin` → 网关没有剥离客户端 `X-Trim-*` 头，立刻停止暴露并排查网关配置。
  - （注意：这条必须走网关测；若直接 curl 后端 TCP 端口绕过网关，本就会拿到 admin，不能据此判断。）
- [ ] **日志无异常绑定**：`app.log` 里监听方式符合预期（socket 或受限 TCP），无异常绑定告警。
